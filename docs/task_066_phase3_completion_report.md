## 1. Executive Summary

Phase 3 of Task 066 implements the **Governed Graph Evolution Pipeline** for the NexusOS Advisory Memory Subsystem. The pipeline bridges the gap between heuristic graph extraction (Phase 2) and durable persistence in SQLite and InMemory stores, enforcing strict multi-tenant isolation, privacy-preserving cascade forgetting, cryptographic identity hashing, optimistic concurrency control (OCC), secret redaction fail-closed boundaries, and immutable supersession lineage.

All extracted graph elements are stored strictly with `verified: false` to ensure advisory-only semantics. Graph facts are completely non-authoritative and possess zero execution authority, zero policy overrides, and zero lease grant capabilities.

## 2. Implemented Components

### 2.1 Canonical Contracts (`packages/contracts/src/memory/evolution.ts`)

- **`GraphEvolutionOperationType`**: Enum declaring `INSERT_NODE`, `UPDATE_NODE`, `SUPERSEDE_NODE`, `INSERT_EDGE`, `SUPERSEDE_EDGE`.
- **`GraphEvolutionOperationSchema`**: Strict discriminated union contract for each operation type carrying atomic payload, version requirements, and deterministic IDs.
- **`GraphEvolutionPlanSchema`**: Immutable plan generated by the engine containing ordered atomic operations, parent record provenance, tenant/workspace context, and expected state preconditions.
- **`EvolutionReceiptSchema`**: Cryptographically verifiable receipt capturing accepted/rejected nodes and edges, superseded lineage lists, duration, and monotonic timestamps.
- **Re-exports**: Re-exported through `packages/contracts/src/memory/index.ts` and `packages/contracts/src/index.ts`.

### 2.2 Governed Graph Evolution Engine (`services/backend/src/memory/graph-evolution-engine.ts`)

- Implements `IGraphEvolutionEngine` interface.
- **Deterministic ID Generation**:
  - Node ID: `node-{SHA256(tenantId:workspaceId:nodeType:canonicalKey)[0..16]}`
  - Edge ID: `edge-{SHA256(tenantId:workspaceId:sourceNodeId:targetNodeId:relationshipType)[0..16]}`
- **Five Governance Gates**:
  1. _Secret Containment Gate_: Scans candidate labels, properties, and metadata via `RedactionFilter.assertNoSecrets()`. Fails closed with `MemorySecretDetectedError` before touching persistence.
  2. _Tenant & Workspace Isolation Gate_: Validates that candidates, parent record, and caller context share identical `tenantId` and `workspaceId`. Violations throw `MemorySecurityViolationError`.
  3. _Parent Memory Status Gate_: Rejects operations when the parent memory record is `TOMBSTONED` or inactive.
  4. _Confidence Threshold Gate_: Discards candidates below `minConfidence` threshold (default 0.50) without polluting graph storage.
  5. _Referential Integrity Gate_: Validates that edge endpoints exist in the plan or active graph state before issuing edge insertions.
- **Refinement vs. Supersession Resolution**:
  - _Refinement_: Compatible property additions update the existing node in-place incrementing `version` via optimistic concurrency control (`expectedVersion`).
  - _Supersession_: Contradictory facts (e.g. status changes or property conflicts) supersede the prior active node (`isCurrent: false`, `validTo: now`, `supersededBy: newId`), create a new immutable node version, and link them via a `SUPERSEDES` edge.

### 2.3 Atomic Persistence Layer (`services/backend/src/memory/sqlite-memory-store.ts` & `memory-store.ts`)

- **`evolveGraph(plan, ctx)`**:
  - SQLite implementation executed inside an atomic transaction: `BEGIN IMMEDIATE ... COMMIT/ROLLBACK`.
  - Enforces version validation: mismatches between `expectedVersion` and current node version abort the entire transaction and rollback immediately.
  - Inserts nodes and edges with `verified: false`, `isCurrent: true`, `sourceRecordId` provenance.
  - Updates temporal windows (`validTo`, `isCurrent`, `supersededBy`) for superseded nodes and edges.
  - Provides failure simulation flags (`simulateFailureInEvolution`, `simulateFailureInEvolutionMidway`) for testing transaction rollbacks.
- **Temporal Query Isolation**:
  - Updated `queryGraph()` in SQLite and InMemory stores to filter by `asOf` timestamp windows and `includeSuperseded` flags (default: `includeSuperseded: false`).
- **Cascade Deletion Hardening**:
  - Hardened `revokeGraphForMemoryInternal()` to physically delete all dependent graph nodes and edges whose provenance traces to a tombstoned parent record.

### 2.4 Service Orchestration (`services/backend/src/memory/memory-service.ts`)

- Added `evolutionEngine` and `autoEvolveGraph` options to `MemoryServiceOptions`.
- Added `getEvolutionEngine()`, `evolveMemoryGraph()`, and `evolveGraphFromCandidates()`.
- Connected non-blocking post-commit evolution triggers in `createMemory()` and `updateMemory()`. If graph evolution encounters an advisory failure, it logs safely without failing or rolling back the primary memory record transaction.

## 3. Architecture & Pipeline Flow

```
+-----------------------------------------------------------------------------------+
|                            MEMORY WRITE PIPELINE                                  |
|                                                                                   |
|  1. MemoryService.createMemory() / updateMemory()                                 |
|     +-> Validate & Sanitize Record                                                |
|     +-> Atomic Store Transaction (Commit Memory Record)                           |
|     |                                                                             |
|     +-> [Post-Commit Evolution Trigger (autoEvolveGraph: true)]                   |
|         |                                                                         |
|         v                                                                         |
|  2. GraphEvolutionEngine.planEvolution(candidates, ctx)                           |
|     +-> Gate 1: Secret Redaction (assertNoSecrets -> MemorySecretDetectedError)   |
|     +-> Gate 2: Multi-Tenant & Workspace Boundary Verification                   |
|     +-> Gate 3: Parent Record Active & Non-Tombstoned Check                       |
|     +-> Gate 4: Confidence Score Thresholding (>= 0.50)                           |
|     +-> Gate 5: Referential Integrity (Active Endpoint Validation)                |
|     |                                                                             |
|     +-> Entity Resolution & Plan Synthesis                                        |
|         - Deterministic Hashing: node-{SHA256(tenant:ws:type:key)[0..16]}         |
|         - Existing Node Check:                                                    |
|           * Same-entity compatible -> UPDATE_NODE (version + 1, OCC)              |
|           * Contradictory fact    -> SUPERSEDE_NODE + SUPERSEDES Edge             |
|           * Brand new entity       -> INSERT_NODE (version: 1, verified: false)   |
|                                                                                   |
|         v                                                                         |
|  3. IMemoryStore.evolveGraph(plan, ctx)                                           |
|     +-> BEGIN IMMEDIATE TRANSACTION                                               |
|     +-> Verify OCC Preconditions (expectedVersion)                                |
|     +-> Apply Atomic Operations (Inserts / Updates / Supersessions)               |
|     +-> COMMIT TRANSACTION (or ROLLBACK on failure)                               |
|                                                                                   |
|         v                                                                         |
|  4. EvolutionReceipt Generation                                                   |
|     +-> Record accepted/rejected IDs, superseded lineage, timestamp               |
+-----------------------------------------------------------------------------------+
```

## 4. Critical Forgetting Decision & Rationale

| Operation Type                                                                   | Behavior                                                                                              | Temporal History                                                    | Privacy / Compliance Implication                                                                                                             |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Contradictory Fact Update** (Knowledge Correction)                             | Immutable Supersession (`isCurrent: false`, `validTo: now`, `supersededBy: newId`, `SUPERSEDES` edge) | **Preserved** (queryable via historical `asOf` queries)             | Audit trails and lineage are retained; past states can be inspected by administrators.                                                       |
| **Parent Memory Record Tombstoning** (User Forgetting / GDPR / Privacy Deletion) | Physical Revocation & Cascade Deletion (`DELETE FROM memory_graph_nodes WHERE source_record_id = ?`)  | **Purged Completely** (absent from both current and `asOf` queries) | Absolute compliance guarantee: when a user requests forgetting of private data, derived graph facts cannot leak through temporal traversals. |
